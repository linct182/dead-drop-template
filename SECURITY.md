# Security design audit

Dead Drop is for approved, non-confidential home-to-office material only. Its operator must independently confirm that publishing and downloading over public GitHub is authorized. Encryption does not grant permission to distribute restricted content. The CLI requires that confirmation for every preparation and a separate final approval for publication.

## Chosen boundary

The MVP is a local Python standard-library CLI plus official 7-Zip, with no hosted service, runtime Python dependencies, or plaintext automation. Narrow UTF-8 text-format and exact repository-path allowlists keep unknown content out. It deliberately excludes PDFs, Office documents, media, arbitrary binary files, and recursive directory packaging; a robust inspector for those is outside this MVP. Plain UTF-8 files can still contain confidential information. Human review remains essential.

Preparation operates on a private snapshot outside the repo. Every source directory is opened without following symlinks; the final file must be regular, single-link, and stable during reading. Suspicious names, repository ancestors, traversal, devices, duplicate basenames, and Windows-unsafe member names fail closed. Original files are untouched. Default exclusions are displayed, not silently packaged. Content findings are reported by category without secret values; there is no ignore/force option.

Archive creation uses 7z AES-256 with encrypted headers (`-mhe=on`). Verification requires password-protected headers, rejection of a random wrong password, successful integrity testing with the chosen password, encrypted AES member metadata, the exact reviewed manifest, and extraction matching each reviewed size and SHA-256. Empty members are rejected because 7-Zip does not encrypt an empty data stream. Only a verified artifact is copied into `drops/`; private plaintext stays outside the repo throughout.

The receipt under `.git/` ties the ciphertext hash to the reviewed member manifest. Publish pins that ciphertext in temporary storage and repeats verification before staging the exact output. Staged blobs, modes, and paths are audited independently of the working copy. New/changed drops require a matching local receipt, and a pre-push hook scans every outgoing tree to catch historical plaintext even when deleted later. Outgoing commit messages receive the implementation-file heuristic scan. New/updated refs must be branches pointing directly to commits: tags, annotations, and arbitrary object refs are refused rather than bypassing tree inspection. Deleting a ref sends no new content and remains permitted. Publication requires no other staged/tracked changes, no unreviewed local commits, a single matching GitHub origin, a displayed diff and manifest, and exact typed approval. Neither `prepare` nor `check` commits or pushes.

## Password handling: verified platform behavior

Validated locally on macOS arm64 with official Homebrew `7zz` 26.05 and Python 3.9.6. No third-party `7z`/p7zip fallback is accepted. Integration tests repeat the relevant prompt, encryption, and extraction checks against the installed binary; unrecognized prompts or echoed private input fail closed.

The official POSIX console password reader reads a line from stdin without disabling terminal echo itself. Therefore directly invoking it on a terminal is not assumed safe. Python uses `getpass` with its insecure fallback promoted to an error and requires an interactive terminal. The subprocess receives the value only through an anonymous stdin pipe; pipes do not echo. Passwords never enter argv, environment variables, files, receipts, Git, or application output. A subprocess canary check rejects any output containing the password and raw subprocess output is never printed on errors.

Creation needs bare `-p` to request a password. On the tested binary, reading with bare `-p` supplies an empty password instead of prompting; integrity/list/extraction commands omit `-p` and require the expected stdin password prompt. Missing-password listing is also tested using EOF on stdin. Other builds/versions/platforms may behave differently and are refused if these runtime assertions fail. Packaging on Windows is unsupported; Windows is the retrieval environment only.

Passwords must be unique and randomly generated. The minimum length, ASCII restriction, repetition checks, and common-pattern rejection are guardrails, not an entropy estimate. ASCII avoids locale/encoding ambiguities between the tested CLI and Windows extractors. Python and 7-Zip retain transient password copies in memory; reliable zeroization, protection against memory inspection, swap, OS crash dumps, keyloggers, or a compromised host is not provided.

Primary references: [7z format and AES-256](https://www.7-zip.org/7z.html), [official POSIX console password reader](https://github.com/ip7z/7zip/blob/main/CPP/7zip/UI/Console/UserInputUtils.cpp).

## Limitations that remain

- Public archives can be downloaded by anyone forever. Weak/reused passwords permit offline guessing. 7z AES encryption is not a modern authenticated-encryption envelope; archive integrity checks plus a trusted local SHA-256 receipt are not an independent public signature.
- Heuristic scanning misses secrets, personal data, proprietary material, and confidential context. It can also reject harmless text. Approved implementation files receive high-confidence credential/personal-data checks and quoted credential-assignment checks; broader variable-assignment checks apply to payloads, since source code legitimately handles password variables. The fixed GitHub SSH service identity is exempt from the email heuristic. No scanner can distinguish every payload disguised as approved documentation or source code.
- Local hooks can be disabled, bypassed, edited, or omitted by another Git client. These guards are for accidental disclosure through the supported workflow, not enforcement against a malicious local user. Public history and the existing baseline are not proven safe by one successful `check`; outgoing trees receive additional pre-push review. Review implementation changes before committing them.
- Local receipts are trusted user-owned metadata, not signed attestations. A local attacker who can rewrite code, Git configuration, or receipts controls the workflow. Do not run concurrent Git mutations during prepare/publish. SHA-256 pins and final index/HEAD checks catch ordinary changes but do not provide an atomic transaction against hostile concurrent processes.
- Temporary directories use mode 0700 and files use restrictive modes. Normal completion, exceptions, Ctrl-C, and SIGTERM clean them up. SIGKILL, power loss, filesystem snapshots, backups, and SSD behavior can leave recoverable plaintext; deletion is not secure erasure. Use an appropriately protected personal host and encrypted storage. Never use a repository-local TMPDIR.
- GitHub's practical limits are handled conservatively at 25 MiB per artifact/total plaintext and 100 members. No Git LFS or repository-size lifecycle service is introduced. Repeated drops accumulate public history. Unknown formats fail closed rather than being silently scanned incompletely.
- A successful push is not a policy decision. The office browser, network rules, approved extractor, and anonymous download behavior must be verified in the authorized environment. There is no bypass for DLP, authentication, proxy, or download restrictions.

## Validation

Run `python3 -m unittest discover -s tests -v`. Tests use synthetic files and random passwords generated only in memory, create isolated local repositories, and clean external temporary directories. Real `7zz` covers single/multiple-file creation, encrypted headers/member data, wrong-password rejection, integrity checks, and exact extraction. Negative tests cover secret/personal-data patterns, unknown/binary content, unsafe selections, missing tools, weak/empty passwords, no-echo fallback, damaged/tampered archives, staged plaintext, staged-secret/clean-working-copy differences, ignored plaintext, deleted historical payloads, secret-like commit messages, tags, and raw object refs. The launcher and safe branch history are also exercised. Publication tests intercept remote access, commit, and push; they verify approval ordering without contacting or modifying any remote.
